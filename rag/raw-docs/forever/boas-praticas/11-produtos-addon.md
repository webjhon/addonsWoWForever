# Produtos reativos para Alliance e Horde1–60

A utilidade precisa ocorrer enquanto o jogador joga. Um índice de dungeons, catálogo de perks ou caderno manual não satisfaz o padrão profissional como produto principal.

## Contrato de produto

Antes do código, definir dois sinais públicos aplicáveis e um evento de gameplay; explicar como o estado observado escolhe a próxima ação e como a UI avança sem confirmação manual. Exemplos de domínios: XP e nível para estimativa contextual; diário e objetivos para guia; placa e relação pública para destaque de NPC. A funcionalidade só pode ser prometida quando há capacidade/dados suficientes.

## Cenários obrigatórios pertinentes

Primeiro uso com ação clara; progresso observado; perda de dados; desativação; reload; recuperação e troca de intenção. Manual é configuração ou fallback explícito. Nenhum clique transforma uma quest em concluída. Não fabricar coordenadas, fórmulas de XP ou elegibilidade.

Código próprio, identidade Tonho Contrabando, ícone e instalação; testes de transições; ZIP produzido pelos gates; PR para aprovação sem merge. Mocks aprovados não validam hit-testing ou APIs reais.
